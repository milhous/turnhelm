## 3. The structured payload contract (PE-1)

Normative definition:

1. **Classification site.** The once-only emission phase of the settled final message (morning §3.4) first classifies the retained message and captures the payload projection, then invokes the sink exactly as today. Eligibility, emission ordering, once-only semantics, pending-write accounting, and failure-on-write-throw behavior are unchanged; extraction adds no second write and changes no lifecycle outcome. Emission gating is unchanged: no write is *initiated* unless the run is completed-eligible — a cancellation or sink error landing while the final write is in flight may still leave delivered bytes on stdout with a `cancelled`/`failed` receipt (non-transactional delivery, receipt is the authority).
2. **Classifier — the frozen envelope discipline, applied to emission.** With `mode` and an emission text derived from the retained message `m`:
   a. `JSON.parse(m)` succeeds → mode `strict`; emitted text = `m` verbatim (byte-identical to the value; the emitter then appends its single `"\n"` as always, so a message `"{}\n"` still produces stdout `"{}\n\n"` — extractor text and emitted text are specified separately and this is pinned behavior).
   b. Else the first line of `m` parses as one JSON value **and** every remaining line is inert (the moved `inertTrailerLine` rule: a line is inert only if, trimmed of leading whitespace, it opens with no `{`, `[`, or `"`, is no code-fence delimiter, and does not itself parse as JSON) → mode `extracted`; emitted text = exactly the first line's bytes; `trailerBytes` = the byte length of everything after the first line's terminating newline (≥ 1 by construction).
   c. Else if the first line parses as a JSON value but some remaining line is non-inert (a second structured payload, a fence-delimited block, any parseable line) → mode `conflict`; emitted text = `m` verbatim. **Structured content after the payload is never silently dropped**: a conflicting or malformed secondary payload keeps the whole message on stdout so strict consumers continue to reject it, visibly, instead of grading a first answer that was contradicted.
   d. Else (the first line is not a JSON value: prose, empty message, truncated JSON) → mode `unstructured`; emitted text = `m` verbatim.
   The emitted text always flows through the existing `emitMessage` accounting with its `"\n"` append. The empty message keeps morning semantics (`stdout` exactly `"\n"`, mode `unstructured`). Parsing uses the native `JSON.parse` only — once for the whole message, once for the first line, once per trailer line — over already-bounded (≤ 1 MiB) retained text; no handwritten grammar, no per-position retries, no re-serialization anywhere.
3. **Receipt projection.** `receipt.worker` gains `payload: { mode: "strict" | "extracted" | "conflict" | "unstructured", trailerBytes?: number }` — present iff the run's final status is `completed` **and** emission was initiated; absent from every `failed`, `cancelled`, and zero-message `completed` receipt, including a cancellation that lands mid-write after bytes were delivered. `trailerBytes` present iff mode is `extracted`. Bounded, fixed, content-free: no trailer bytes, hashes of trailers, or value shapes are retained anywhere.
4. **Consumer contract.** After a worker start, stdout carries at most one write. When the final message is one JSON value, stdout is exactly that value plus the emitter newline; when it is a payload line plus inert prose, stdout is exactly the payload line plus the newline — machine-parseable by construction in both cases, original bytes preserved. When the message carries conflicting structured content or is not JSON-shaped, stdout is the whole message verbatim and the receipt says so (`conflict` / `unstructured`). Success is still never inferred from stdout; exit code and receipt remain the only success evidence. This is a delimitor, not a validator — payload contents are not checked, and stdout remains not a redactor.
5. **One frozen definition.** `envelopePayload` and `inertTrailerLine` move verbatim from `test/live-acceptance.ts` into `src/payload.ts`; the harness re-imports them (re-exports preserved for existing import sites, `test/custom-round.ts` included). The 2026-10-12 120-case no-regression matrix carries over against the moved definitions, and the emission classifier adds its own matrix pinning mode + emitted text for every case shape. Producer and consumers judge one definition; drift between product and harness envelope semantics becomes impossible by construction.
6. **Security and privacy.** In `extracted` mode strictly fewer worker-controlled bytes cross the output boundary, and fewer are retained anywhere. No new trust boundary opens: classification is native parsing over bounded retained text; the stderr boundary is untouched by construction.
7. **Performance.** At most one whole-message parse plus one per-line parse over text already bounded by the frame cap, at settlement only. No timers, channels, caps, or config keys. Negligible against worker runtimes measured in tens of seconds.
