# v0.2.0 Validation Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make worker failures attributable from sealed evidence (failure deadline with group-cleanup contract, taxonomy + hash instead of message text, attribution fields, evidence projection), eliminate the adjudicated stdout footer false-failure class (narrow two-rule envelope), run the routing criteria v2 policy-alignment experiment with predeclared gates, and close the `BASH_ENV`/`ENV` re-import hole.

**Architecture:** Three surgical `src/` changes (`src/codex-events.ts`, `src/codex.ts`, `src/cli.ts`, `src/systemone.ts`) plus harness changes in `test/live-acceptance.ts`; hermetic tests per workstream; a free-local-call calibration campaign whose artifacts live outside the repo and whose sealed record lands in `docs/validation/2026-10-12-calibration-v2.md`; documentation sync last.

**Tech Stack:** TypeScript (strict, ESM), `node:test` via `pnpm test` (build + `node --test dist/test/*.test.js`), Node ≥ 24; local Laya service (existing venv, health-checked, owned, stopped after use) for Task 6 only.

**Spec:** `docs/superpowers/specs/2026-10-12-v020-hardening-design.md` (post round-1 astra revision; its §10 records all eight dispositions — taxonomy-not-text, grace cleanup contract, action-not-causation attribution, two-rule envelope, policy-alignment framing, tuning/confirmation data boundary with fresh authored holdout, enumerated blocking gates, evidence projection).

- Diff surface exactly: `src/codex-events.ts`, `src/codex.ts`, `src/cli.ts`, `src/systemone.ts`, `test/codex-events.test.ts`, `test/worker.test.ts`, `test/task-routing.test.ts`, `test/live-acceptance.ts`, `test/live-acceptance.test.ts`, `README.md`, `.agents/skills/turnhelm-routing/SKILL.md`, new `docs/validation/2026-10-12-calibration-v2.md`. Nothing else; no dependencies, no schema bumps (config v1, manifest/corpus v2), no changes to the eight frozen calibration stimuli or `workerReadonlyTask`/`workerWriteTask` texts.
- Inherited invariants unchanged: one receipt; journal-before-worker and journal hash-only; sticky-failed irreversibility; kill-ladder reach and TERM→KILL escalation; one attempt per eligible backend with the 3/4–1/4 split; Jev triple gate; caps and once-only manifests; exit codes 0/1/2/3/4/130/143 with their existing meanings.
- Confidentiality (release-blocking canaries): no native error message text — no short secret, no `password=`-shaped string, no task-text sentence, no 20+-char substring of the raw message — may appear in stdout, stderr diagnostics, receipts, journal, or evidence. The taxonomy class and `errorSha256` are the only failure-text-derived outputs.
- `ownedShutdown` documents an attempted parent shutdown, never causation; the `signal` union is `SIGINT | SIGTERM | SIGKILL`; claims about the case-14 class are bounded-observability claims.
- Task 6 is free local calls only: no paid APIs, no hosted Jev, workers never spawn; total tuning calls ≤ 200; confirmation sets exactly as enumerated in spec §5; a failed gate blocks the criteria change (v1 text stays) after at most one retune with a newly authored holdout.
- All docs/comments in English. Conventional Commits. No push, no branch creation beyond the existing `feat/v020-hardening`, no PR without explicit user instruction.
- Gates: `pnpm test` green; `pnpm run test:coverage` green (80/80/80 lines/branches/functions on `dist/src/**`).

### Task 3: failure deadline, cleanup contract, attribution, receipt (WH-1 §3.1, §3.3)

**Files:**
- Modify: `src/codex.ts` (`executeWorker`: dispatch, close handler, `beginShutdown`, `finish`, `WorkerResult`)
- Modify: `src/cli.ts` (`receipt.worker` assembly ~lines 236–241; one `turnhelm: worker-failed: <class>` stderr diagnostic)
- Test: `test/worker.test.ts`

**Interfaces:**
- `WorkerResult` gains `signal?: "SIGINT" | "SIGTERM" | "SIGKILL"` (observed child death signal when `code === null` and the signal is in the union), `ownedShutdown: boolean` (required on every worker result; `false` when no parent-initiated ladder ran), `failureClass?: FailureClass` (also emitted as `"unknown"` for any failed status that saw no failure event), `errorSha256?: string`.
- `FAILED_EXIT_GRACE_MS = 5000`. First `turn.failed`: `stickyFailed = true`, start one deadline. **Deadline expiry discharges the obligation unconditionally, regardless of leader liveness** — leader alive, or exited with `close` still pending on a descendant holding inherited stdio, expiry calls `beginShutdown()` (existing TERM→KILL ladder, `ownedShutdown` set). Leader `close` with `stickyFailed` and no shutdown yet ⇒ group-cleanup obligation: set `shutdownDischarged = false`, poll `signalGroup(0)` — group gone ⇒ discharge; alive ⇒ `ownedShutdown = true`, run the existing ladder, discharge on completion. Repeated `failed` events never restart the deadline. `onAbort`/`recordFailure` clear the deadline and call `beginShutdown()` immediately (existing TERM grace unchanged, never restarted by the deadline). `finish()` disposes the deadline timer; nothing fires after settlement. Drain semantics after shutdown starts are unchanged (buffered frames dropped). The `failed` dispatch emits exactly one fixed diagnostic line carrying only the taxonomy class.
- Receipt: the executed-worker `worker` object carries `signal`/`failureClass`/`errorSha256` when present and `ownedShutdown: boolean` **always** (required, `false` on natural paths) — no absent-vs-false ambiguity downstream. `workerExit` unchanged.

- [ ] **Step 1: Failing tests** — (a) `turn.failed` then leader close within grace: own exit code recorded, `ownedShutdown: false` when the group is already gone; (b) same, but a TERM-ignoring descendant with independent stdio survives: cleanup ladder runs, settlement waits for discharge, `ownedShutdown: true`; (c) deadline expiry with leader alive: ladder runs, `ownedShutdown: true`; (c′) deadline expiry with the leader **exited but not closed** (a same-group descendant holds the inherited stdio, so `close` never fires): ladder still runs and settles — the inherited-stdio hazard case; (d) repeated `failed` events: one deadline only; (e) caller cancellation during grace supersedes immediately (cancelled status, ladder, no grace extension); (f) transport failure during grace supersedes immediately with its own cause; (g) no timer callback after settlement (settle-inspecting spy or post-settle frame injection); (h) `stickyFailed` still irreversible: completion after `failed` settles failed; (i) signal death: `signal: "SIGTERM"` with code 143 mapping unchanged, and SIGINT/SIGKILL variants; (i′) eventless failure (non-zero exit, no failure events): `failureClass: "unknown"`, `ownedShutdown: false`; every executed-worker receipt carries a boolean `ownedShutdown`; (j) diagnostic line is exactly `turnhelm: worker-failed: <class>`; (k) **end-to-end receipt canary**: a fake worker emitting hostile error events (canary literals: `password=p@ss.word!`, a short bearer token, a task-text sentence) through the real CLI — the emitted receipt, stderr diagnostics, and evidence each asserted to contain none of the canary literals individually, nor any 20+-char substring of the raw message.
